01ภาพรวมโปรเจกต์

HomeChef.Api เป็น REST API สำหรับสร้าง อ่าน แก้ไข และลบสูตรอาหาร แต่ละสูตรมีรายละเอียดหลัก วัตถุดิบหลายรายการ และขั้นตอนการทำหลายขั้นตอน ส่งและรับข้อมูลเป็น JSON

04Workflow รายเส้นทาง

POST สร้างสูตรอาหาร

  1. รับและ bind JSON เป็น CreateRecipeRequest; ตรวจ required fields และ business validation หากผิดคืน 400 ก่อนเขียนข้อมูล
  2. สร้าง Recipe โดยแอปกำหนด GUID ใหม่; trim ชื่อและ normalize optional strings ให้เป็นข้อความที่ trim แล้วหรือ null
  3. สร้าง ingredients โดยใช้ตำแหน่ง Array + 1 เป็น position; ปัด quantity เป็นทศนิยม 2 ตำแหน่ง
  4. สร้าง instructions โดยใช้ตำแหน่ง Array + 1 เป็น step_number และ trim description
  5. db.Recipes.Add และ SaveChangesAsync บันทึกทั้ง graph โดย EF ใช้ transaction ของการบันทึกครั้งนั้นกับฐานข้อมูล relational
  6. แปลงเป็น RecipeResponse; คืน 201 และ Location ชี้ไป GET ของสูตรที่สร้าง

GET อ่านรายการและอ่านรายตัว

ทั้งสองแบบอ่านผ่าน query filter DeletedAt == null และ AsNoTracking เพราะไม่มีการแก้ไขข้อมูล ใช้ Include วัตถุดิบ/ขั้นตอน และ AsSplitQuery แยก query โหลดความสัมพันธ์ ก่อนจัดลำดับรายการย่อยใน ToResponse

  • รายการ: Count สูตรที่ยังใช้งาน → คำนวณ offset → ตรวจหน้าว่าง → OrderBy ID → Skip/Take → โหลดรายการย่อย → คืนจำนวนรวมและ record
  • รายตัว: ค้นจาก ID → ถ้าไม่พบคืน 404 → ถ้าพบคืน RecipeResponse 200

  • PUT ใช้ validation และ mapping ร่วมกับ POST; validation เกิดก่อนค้นหา ID ดังนั้น request ไม่ถูกต้องอาจได้ 400 ก่อนการตัดสินว่า ID มีหรือไม่
  • สูตรหลักยังใช้ ID เดิม แต่ลบ ingredients/instructions เดิมจริง แล้วสร้างรายการย่อยใหม่ทั้งหมด จึงไม่ใช่การแก้รายการย่อยทีละ ID
  • Save ครั้งแรกปล่อย unique keys (recipe_id, position) และ (recipe_id, step_number) ก่อนเพิ่มชุดใหม่
  • Save ทั้งสองครั้งอยู่ใน transaction เดียว หากมี exception จะไม่ commit และ rollback ข้อมูลเดิมกลับมา ทั้งรายละเอียดสูตรและรายการย่อย
  • ส่ง optional field เป็น null เพื่อเคลียร์ค่าได้; หากไม่ส่ง optional field ค่านั้นก็เป็น null และถูกเคลียร์เช่นกัน เพราะเป็น Full Update

DELETE Soft Delete

แนวคิด SQL ที่สอดคล้องกับการทำงาน (ไม่ใช่ SQL ที่คัดจาก runtime):
UPDATE public.recipes
SET deleted_at = <เวลาปัจจุบัน UTC>
WHERE id = <recipe ID> AND deleted_at IS NULL;

ใช้ ExecuteUpdateAsync อัปเดตเฉพาะ timestamp โดยไม่ต้องโหลด Entity หาก affected rows = 0 คืน 404 มิฉะนั้นคืน 204 ไม่มี body แถวสูตรและรายการย่อยยังอยู่ การอ่านและ PUT ครั้งต่อไปจะไม่พบสูตรนั้น และ DELETE ซ้ำได้ 404 ปัจจุบันไม่มี API กู้คืน

DB health

เปิด connection → รัน SELECT 1 → ถ้าได้เลข 1 คืน connected 200; หากเปิด connection/คำสั่งเกิด NpgsqlException คืน unavailable 503 และถ้าได้ค่าที่ไม่ใช่ 1 คืน unhealthy 503 การตรวจนี้ไม่อ่านตารางสูตรและไม่ยืนยันสิทธิ์ CRUD หรือคอลัมน์ deleted_at

05Pagination

Query parameterค่าเริ่มต้นช่วงที่ยอมรับความหมาย
page1จำนวนเต็ม 1–2,147,483,647เลขหน้า เริ่มนับจาก 1
itempage10จำนวนเต็ม 1–100จำนวนสูตรสูงสุดต่อหน้า
GET /api/recipes?page=2&itempage=10

offset = (page - 1) × itempage
totalRecord = จำนวนสูตรทั้งหมดที่ deleted_at IS NULL
record = สูตรในหน้าที่ขอ หลังเรียง id จากน้อยไปมาก

totalRecord ไม่ใช่จำนวนรายการในหน้าและไม่ใช่จำนวนหน้า การเรียงใช้ ID ไม่ใช่เวลาสร้าง เมื่อ offset มากกว่าหรือเท่าจำนวนรวม คืน record: [] กับ 200 โดยยังคงจำนวนรวมไว้ Offset คำนวณแบบ long ก่อนตรวจขอบเขต เพื่อไม่ให้ล้นเมื่อเลขหน้าสูงมาก

ตัวอย่าง: มีสูตรที่ยังใช้งาน 25 สูตร ขอ page=3 และ itempage=10 จะได้ totalRecord=25 และ record 5 สูตร; ขอ page=4 จะได้ totalRecord=25 และ record ว่าง

Keys, indexes และการลบที่เกี่ยวข้อง

  • แต่ละตารางมี primary key ที่ id; ทั้งสองตารางย่อยมี FK recipe_id → recipes.id
  • Unique index (recipe_id, position) ป้องกันตำแหน่งวัตถุดิบซ้ำภายในสูตร และ (recipe_id, step_number) ป้องกันเลขขั้นตอนซ้ำภายในสูตร
  • EF กำหนด DeleteBehavior.Cascade สำหรับการลบแถวสูตรจริง แต่ DELETE API เปลี่ยน timestamp เท่านั้น จึงไม่ทำให้รายการย่อยถูก cascade delete
  • กฎมากกว่า 0, unit ต้องมีเมื่อมี quantity และ URL ต้องเป็น HTTP/HTTPS อยู่ใน validation ของ Controller; EF mapping ที่อ่านไม่ได้ประกาศ CHECK constraints สำหรับกฎเหล่านี้ จึงไม่ควรถือว่าเขียน SQL ตรงแล้วจะได้รับการตรวจแบบเดียวกัน

Fieldกฎของ POST / PUT

servingsต้องมีค่าเป็น integer มากกว่า 0
ingredientsต้องมีอย่างน้อย 1 รายการ และห้ามมีสมาชิก null

Normalization: optional strings ที่เป็น null, ว่าง หรือมีแต่ช่องว่าง กลายเป็น null; ข้อความที่เหลือถูก trim ชื่อสูตร/ชื่อวัตถุดิบ/description ของขั้นตอนถูก trim เช่นกัน

Quantity: ปัดด้วย MidpointRounding.AwayFromZero ให้เหลือ 2 ตำแหน่ง เช่น 1.235 → 1.24 และค่าบวกเล็กมากที่ปัดเหลือ 0 เช่น 0.001 จะเก็บเป็น 0.01 แทน ไม่ใช่ 0

09ตั้งค่า รัน และเตรียมฐานข้อมูล

  1. ติดตั้ง .NET SDK 10 และเตรียม PostgreSQL ที่มีทั้งสามตารางตาม mapping; SQL script ที่มีอยู่เป็นการเพิ่มคอลัมน์/กำหนดสิทธิ์ ไม่ใช่สคริปต์สร้างทุกตารางจากศูนย์
  2. ตั้ง ConnectionStrings:HomeChefDb ใน User Secrets หรือ ConnectionStrings__HomeChefDb ใน environment ตาม environment ที่ใช้ ไม่ใส่รหัสผ่านจริงในไฟล์ที่ commit
  3. ใช้เจ้าของตาราง เช่น postgres รันสคริปต์เพิ่ม deleted_at บนฐานข้อมูลที่แอปเชื่อมจริง แล้วกำหนดสิทธิ์ให้บัญชี runtime ตามความจำเป็น
  4. restore/build และรันโปรไฟล์ http หรือ https; เปิด Swagger เฉพาะเมื่อแอปอยู่ใน Development
